## 📰 今日AI观点

### Simon Willison 博客 (simonwillison.net)

**GPT-5.6 三剑客发布 (Jul 9)**
OpenAI 发布了 GPT-5.6 系列，分 Luna ($1/$6 per M tok)、Terra ($2.50/$15)、Sol ($5/$30) 三个档次。百万 token 上下文窗口，128K 输出上限，知识截止 2026年2月。Simon 亲测后评价："Sol 确实很强，但我没觉得它比 Claude Fable 在复杂编码任务上更好。"

关键洞察：OpenAI 在 Agent's Last Exam 上宣称胜出 Fable 5 13.1 分，但在 SWE-Bench Pro 上反而被 Fable 5 碾压（80% vs 64.6%）。更妙的是 OpenAI 在发布前一天发了篇博客说 SWE-Bench Pro 约 30% 的任务存在缺陷——典型的"先拆台再比赛"策略。

新 API 亮点：Programmatic Tool Calling（模型可以写 JS 来编排工具调用）、Multi-agent 原生支持（子 agent 模式直接内建在 API 里）、Prompt cache breakpoints（像 Claude 那样手动标注缓存断点）。

**sqlite-utils 4.0 (Jul 7)**
Simon 发布了 sqlite-utils 4.0，主打数据库迁移、嵌套事务、复合外键。他分享了一个很有意思的工作流：用 Claude Fable 5 做代码审查，Fable 写了 12 个测试脚本、发现了 4 个发布阻塞 bug 和 10 个额外问题。"如果你给它一个开放的目标，Fable 在 API 设计上的品味真的很好，而且 relentlessly proactive。"

## 🚀 值得关注的项目

### 1. [ponytail](https://github.com/DietrichGebert/ponytail) ★81K
"让你的 AI agent 像团队里最懒的资深工程师一样思考——最好的代码是你没写的代码。" 这本质上是一个 Claude Code 的思维框架/插件，教 agent 怎么偷懒（即怎么用最少的代码解决问题）。对 PM 的参考价值：好产品不是功能多，而是"不做什么"的决策能力。这个项目是对"少即是多"哲学的工程实现。

### 2. [MiMo-Code](https://github.com/XiaomiMiMo/MiMo-Code) ★12K
小米开源的「模型与 Agent 共同进化」框架。TypeScript 实现，CLI 工具。标志性事件——中国大厂在开源 AI coding agent 赛道加码。值得 fork 的原因：看看国内团队的 agent 设计思路和海外有什么不同。

### 3. [loop-engineering](https://github.com/cobusgreyling/loop-engineering) ★7K
AI coding agent 的 Loop Engineering 模式：设计系统来 prompt 和编排 agent。说白了就是「agent 的 DSL/框架层」。对 AI PM 的参考：当 agent 编程成为主流，产品经理需要理解"编程"正在从写代码变成设计高质量 prompt + 反馈循环。

### 4. [DeepSpec](https://github.com/deepseek-ai/DeepSpec) ★6.6K
DeepSeek 开源的投机解码(speculative decoding)训练和评估全栈代码库。对推理加速有直接价值。

### 5. [colibri](https://github.com/JustVugg/colibri) ★6.4K
纯 C 实现，零依赖，在 25GB 内存的消费级机器上跑 GLM-5.2（744B MoE）。"Tiny engine, immense model"——本地大模型推理的极致优化。

## 🎯 PM成长建议

### 今天的核心学习：理解「Agent 编程」范式转换

从今天的多个信息源交叉来看，一个清晰的趋势浮现：
- OpenAI 的 GPT-5.6 把 multi-agent 做进了核心 API
- Simon 用 agent 做代码审查，agent 替他找到 14 个 issue
- ponytail 在教 agent 怎么偷懒（怎么更高效）
- loop-engineering 在给 agent 编程设计 DSL
- DeepSpec / colibri 在让大模型跑得更快更便宜

**给 tiantian 的可执行建议：**

**本周小目标（30分钟）：** 去 fork [loop-engineering](https://github.com/cobusgreyling/loop-engineering) 项目，跑通它的 CLI demo。花 15 分钟看完它的 README 和模式文档，然后问自己一个问题："如果我的产品要接入 AI agent，我需要设计什么样的反馈循环？"

**为什么是这个而不是别的：**
- 它是最「产品思维」的——loop-engineering 本质上在解决"如何设计 agent 的行为规范"，这跟你设计产品功能规范是一回事
- 30分钟内可以跑通，门槛低
- 它是跨模型的（不绑定特定平台），学了通用性强

**长期关注：** Lilian Weng 的「Scaling Laws, Carefully」值得完整读一遍。当你是 PM 却能和工程师用同一套语言讨论 scaling laws 时，你的价值翻倍。
