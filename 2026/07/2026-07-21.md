### 实战经验 (Simon Willison)

- **Kimi K3 评测：2.8T 参数、$3/$15 per M token 定价**，成为最贵的中国模型。Simon 用 "pelican riding a bicycle" 测试花掉了 25 美分/次（13,241 个 reasoning tokens）。核心发现：K3 目前只有一个 "max" 推理档位，85 token 隐藏系统提示。
- **GPT-5.6 三兄弟（Luna/Terra/Sol）发布**，OpenAI 带来 Programmatic Tool Calling（模型可编写 JavaScript 编排工具调用）、Multi-agent（子 agent 并行工作）等新 API 能力。Simon 评价："Sol 很能干，但在复杂编程上感觉没超过 Fable"。
- **sqlite-utils 4.0 发布**，Simon 详细讲述了如何用 Claude Fable 做代码审查——Fable 发现了 4 个 release blocker + 10 个额外 bug，深度解读了"让 AI 审查 AI 代码"的最佳实践。
- **核心心得**：Simon 的 pelican 测试 21 个月了，虽然不再是好 benchmark，但作为"hello world"测试新模型仍然有价值。更重要的启示是：真正衡量模型能力的是 agentic tool calling 和长对话中的工具可靠性。

## 🚀 值得关注的项目

### 1. n8n-io/n8n (★197K)
**为什么值得看**：n8n 是开源工作流自动化平台，现已内置原生 AI 能力。对 AI PM 来说，这是理解"AI + 工作流编排"产品形态的最佳参考。它展示了如何将 LLM 调用、RAG 检索、工具调用封装为可视化节点，类似但更开源版的 LangFlow。
**学习价值**：研究其 AI 节点设计思路——如何把 prompt 模板、模型选择、知识库检索做成可配置、可复用的产品模块。

### 2. firecrawl/firecrawl (★153K)
**为什么值得看**：API-first 的网页抓取和交互工具，正是我们今天做信息聚合时遇到的痛点的直接解决方案。它把 web scraping、crawling、interaction 封装成统一 API。
**学习价值**：如果 tiantian 在做任何数据采集类的 AI 产品（比如竞品分析、信息聚合），FireCrawl 是开箱即用的基础设施。建议 fork 下来跑一遍 playground。

### 3. langflow-ai/langflow (★152K)
**为什么值得看**：构建和部署 AI agent 和工作流的可视化工具。对比 n8n 更偏 AI-native，专注于 LLM 应用的编排。
**学习价值**：作为 AI PM，langflow 的节点设计（如何拆解 agent 组件为可组合模块）本身就是产品设计的范本。值得花 30 分钟理解其组件抽象层次。

## 🎯 今日 PM 成长建议

### 1. 立即 fork 的项目 → langflow-ai/langflow
花 15 分钟在本地跑起来 langflow 的 playground，随便拖几个节点拼一个简单的 RAG agent。**目标不是写出代码，而是理解 AI 产品的组件化设计语言**——什么时候需要 memory、怎么拆 tool calling、prompt template 的策略。这份认知会直接体现在你设计 AI 产品的 PRD 质量上。

### 2. 必读的文章 → Lilian Weng 的「Scaling Laws, Carefully」
https://lilianweng.github.io/posts/2026-06-24-scaling-laws/
如果今天只看一篇技术文章，就是这篇。作为 AI PM，理解 scaling laws 意味着你能：
- 判断"加数据还是加参数"的产品决策哪个更划算
- 理解为什么推理模型需要那么多计算资源
- 在跟算法团队讨论资源分配时有共同语言

### 3. 本周 30 分钟小目标 → 实践 Simon Willison 的 "pelican test" 工作流
Simon 的核心方法论值得每个 AI PM 学习：
1. 用 `llm` CLI 或 OpenRouter，用同一个 prompt 测试 3 个不同模型的输出
2. 记录 token 消耗和耗时
3. 对比质量和价格

**具体操作**：用你常用的 API（DeepSeek/OpenAI/Claude），对同一个 prompt 调用不同档位的模型（如高/低推理强度），做一个简单的二维对比表。你会在 30 分钟内获得对"推理成本 vs 质量"的直观体感，这在写 AI 产品定价方案时极其有用。
