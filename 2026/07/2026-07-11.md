### Simon Willison (@simonw)

**1. GPT-5.6 三兄弟发布：Luna / Terra / Sol**
GPT-5.6 Sol 在 Agents' Last Exam 以 53.6 分超越 Claude Fable 5（40.5 分），但 SWE-Bench Pro 上 Fable 5 反而以 80% 碾压 Sol 的 64.6%。Simon 的直评："Sol 很厉害，但在我用的复杂编码任务上，还没觉得比 Fable 好。" 新 API 亮点包括：**Programmatic Tool Calling**（让模型自己写JS编排工具调用）、**Multi-agent**（子Agent模式进入核心API）、**Prompt Cache Breakpoints**（对标Claude的缓存机制）。

**2. shot-scraper video：让AI Agent录制产品演示视频**
Simon用GPT-5.5在Codex Desktop里写了一个新功能——通过YAML的storyboard定义，让Playwright录制web操作的视频demo。典型工作流：Agent自己跑一个dev server → 执行操作 → 录制mp4。他的原话："这个功能我2024年2月就开了issue，没有coding agent我几乎不可能有时间做。"

**3. Moebius 0.2B 图像补全模型 → 浏览器**
Simon用Claude Code把0.2B参数的图像补全模型从PyTorch/CUDA移植到了浏览器WebGPU。典型的"并行项目"——在主项目等Codex跑代码的间隙，开个副项目。

## 🚀 值得关注的项目

### 1. headroomlabs-ai/headroom ⭐58k
**压缩工具输出/RAG块60-95% token，答案不变。**
为什么值得看：作为AI产品经理，token成本直接决定你的产品毛利率。这个项目提供了Library、Proxy、MCP Server三种接入方式。如果你在做客服/文档问答类产品，这是你下周就该试的工具。

### 2. bytedance/deer-flow ⭐76k
**字节跳动的长周期SuperAgent框架——自带沙箱、记忆、工具、子Agent和消息网关。**
为什么值得看：大厂出手的Agent框架，支持分钟到小时级的复杂任务。对标的是AutoGPT这代产品在长任务稳定性上的痛点。如果你在规划Agent产品路线图，研究它的任务分解和状态管理机制会很有启发。

### 3. x1xhlol/system-prompts-and-models-of-ai-tools ⭐141k
**Curated collection：Claude Code、Cursor、Devin、Windsurf等几乎所有AI工具的system prompt和内部模型信息。**
为什么值得看：想理解竞品怎么做AI Agent的？这里直接告诉你他们的system prompt怎么写。对AI产品经理来说，这是竞品分析的金矿。

### 4. google-gemini/gemini-cli ⭐105k
**Google官方的终端Agent，开源。**
为什么值得看：Google终于开源了他们的Agent CLI，支持多模态+工具调用。如果你的产品在做AI coding assistant方向，看Google怎么设计交互值得研究。

### 5. zhayujie/CowAgent ⭐45k
**开源的全渠道AI助手框架（原chatgpt-on-wechat作者新作）。**
为什么值得看：支持多模型、多渠道（微信/企微等）、记忆和知识库。如果你在国内做AI助手/客服产品，这是最贴近落地场景的开源方案。

## 🎯 PM成长建议

### 核心建议：读 Simon 的 shot-scraper video 博文，学"Agent 自录 Demo"模式

**为什么这件事重要：**
Simon 原文最有价值的一句话不是技术细节，而是他的产品思路——"让coding agent在完成代码后自动录制一个操作视频，证明它真的work了。" 这不仅是开发效率问题，更是**AI产品交付质量**的问题。

作为AI产品经理，你早晚会遇到的情况是：AI开发出来的功能，测试时看起来对，上线后在某些边界条件下炸了。Simon 的方案——用 storyboard YAML 定义"用户操作路径"，让Agent自动录视频——本质上是一种**自动化验收测试的AI原生版本**。

**本周可实践的小目标（30分钟）：**

1. 打开 Simon 的 [shot-scraper video 文档](https://shot-scraper.datasette.io/en/stable/video.html)，读一遍 YAML storyboard 的格式
2. 想想你最近在跟的项目里，有没有"一个用户典型的端到端操作路径"（比如：登录→搜索→查看详情→下单）
3. 用手写一个storyboard.yml描述这个路径，哪怕你还不能真的跑它——"先定义验收标准，再开发"这个习惯，比任何工具都值钱

**延伸思考（10年复利视角）：**
GPT-5.6 的 API 新加了 Programmatic Tool Calling 和 Multi-agent 子Agent模式。这意味着什么？未来不是人跟AI对话，而是AI Agent在后台编排其他AI Agent。你作为PM，核心技能不再是写PRD，而是设计**Agent之间的交互协议和验收标准**。今天写 storyboard.yml 训练的能力，就是明天设计 multi-agent 工作流的原型。
