## 📰 今日AI观点

### Simon Willison 博客 (Jul 9 - Jun 22)

**① GPT-5.6 家族发布：Luna / Terra / Sol**
- OpenAI 发布三代模型（小/中/大），定价 Luna $1/$6, Terra $2.50/$15, Sol $5/$30 per 1M tokens
- Agent's Last Exam 基准测试中 Sol（53.6）超过 Claude Fable 5（40.5）13.1 分，但 SWE-Bench Pro 上 Fable 5（80%）大幅领先 Sol（64.6%）
- **关键洞察**：OpenAI 在发布前专门发文质疑 SWE-Bench Pro 的可靠性，称 "~30% 的任务是 broken"，这正是因为自家模型在这个基准上输了
- 新 API 功能包括：Programmatic Tool Calling（模型可编写 JavaScript 编排工具调用）、内置 Multi-agent 支持（子 agent 模式进入核心 API）、Prompt cache breakpoints
- Simon 实测：*"Sol 确实很强，但迄今为止在复杂编码任务上，我感觉还不如 Fable"*

**② sqlite-utils 4.0 发布，引入数据库迁移系统**
- Simon 将 3 年前从独立包 `sqlite-migrate` 开发的迁移系统正式纳入 `sqlite-utils`
- 使用 Python 定义迁移：`@migrations()` 装饰器 + `table.transform()` 方法（实现 SQLite 官方推荐的变通模式）
- 支持 `db.atomic()` 嵌套事务、compound foreign keys
- **对 PM 的启示**：Simon 的整个 Datasette/LLM 生态系统所有代码都由 Claude Code/Codex Desktop 编写——这是"一个人 + AI agent"构建完整开源生态的范本

**③ shot-scraper video：让 AI agent 自动录制产品演示视频**
- 通过 YAML storyboard 定义操作步骤（click/fill/wait_for/scroll），Playwright 自动录制
- 更具突破性的是：整个 storyboard 是由 GPT-5.5 xhigh 在 Codex Desktop 中自动生成的
- Simon 的模式："coding agent 只要看 `--help` 输出就能用工具，就像在工具里绑了个 SKILL.md"
- 对 PM 的价值：AI agent 不仅能写代码，还能自动录制产品 demo 视频

**④ 用 Claude Code 将 Moebius 0.2B 图像修复模型移植到浏览器**
- Simon 在等待 Codex 完成 Datasette 大重构的间隙，顺便完成了这个 side project
- 核心技巧：并行使用多个 agent——一个做大活儿，另一个做 side project

## 🚀 值得关注的项目

### 1. ⭐ ollama (176K stars) — 本地运行大模型的标配
**URL**: https://github.com/ollama/ollama
**最新动态**: 现已支持 Kimi-K2.6、GLM-5.1、MiniMax、DeepSeek、gpt-oss、Qwen、Gemma 等
**为什么要看**: 本地 LLM 部署的工业标准。作为 PM，花 30 分钟装一个 ollama 跑通本地模型，理解 prompt latency、model switching 对产品体验的影响，比读十篇论文更有效。

### 2. ⭐ LLMs-from-scratch (99K stars) — 从零实现 ChatGPT-like LLM
**URL**: https://github.com/rasbt/LLMs-from-scratch
**为什么要看**: Sebastian Raschka 写的从零实现 LLM 的 PyTorch 教程，step by step。如果你想理解 Transformer 内部机制，这是最好的起点。

### 3. ⭐ claude-mem (87K stars) — AI 持久化记忆方案
**URL**: https://github.com/thedotmack/claude-mem
**为什么要看**: "捕获 agent 在会话期间做的所有事，压缩后注入到后续会话"。这和我们的 Hermes Agent/Engram memory 机制高度相似——可以看看别人是怎么做 memory compression 的。

### 4. ⭐ AutoGPT (185K stars) — 自主 agent 先驱
**状态**: 持续活跃，但注意它的实用价值更多在概念层面（agent 架构设计），实际生产中使用需要大量定制。
**PM 视角**: 理解 agent 架构的"Hello World"。

## 🎯 PM 成长建议（今日重点）

**建议标题：理解"模型能力 ≠ 产品能力"——从 GPT-5.6 vs Fable 的 benchmark 博弈中学习**

**核心洞察**：OpenAI 发布 GPT-5.6 Sol 时宣称 Agent's Last Exam 上超越 Fable 5 近 13 分，但 SWE-Bench Pro 上 Fable 5 反过来领先 Sol 15 分。更有趣的是，OpenAI 在发布前一天专门发文（"Separating Signal from Noise"）质疑 SWE-Bench Pro 有 ~30% 的测试用例有问题。

**作为 PM，你应该学到什么？**
1. **Benchmark 是选择性武器**——每个厂商都会选择对自己有利的基准，就像每个 PM 选对自己有利的 metric。看评测不要只看分数，要看评估了什么能力
2. **实测比跑分重要**——Simon Willison 的结论最诚实："Sol 很厉害，但在复杂编码任务上还是不如 Fable"。产品选型要自己跑场景，不要信厂商的 benchmark table
3. **API 功能比模型本身重要**——GPT-5.6 的新 API（Programmatic Tool Calling、Multi-agent、Prompt cache breakpoints）对产品架构的影响可能比模型质量提升更大

**本周可实践的小目标（30 分钟内）**：
1. 阅读 Lilian Weng 的 "Scaling Laws, Carefully" 的摘要部分（15 分钟），了解 scaling laws 的真正含义
2. Fork 并本地运行 `claude-mem` 或阅读其 README（15 分钟），对比 Hermes 的 Engram memory 机制——不同的 memory compression 策略直接影响到 AI 产品的"记忆能力"设计

**一句话**：今天你学到的最重要一件事是：模型的 benchmark 是厂商的营销工具，不是你的选型依据。自己试，最真实。
