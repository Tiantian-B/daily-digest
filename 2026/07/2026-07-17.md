## 📰 今日AI观点

### Simon Willison 博客

**1. Kimi K3 发布：2.8万亿参数的开源模型**
Moonshot AI 发布了 Kimi K3，号称"首个开源3T级模型"。Simon 用 OpenRouter 跑了他经典的"鹈鹕骑自行车"SVG生成测试——成本25美分（13,241个推理token）。关键点：
- 定价 $3/$15（输入/输出每百万token），是国产模型中最贵的，和Claude Sonnet系列看齐
- Agentic Arena 前端编码排行榜上超越 Claude Fable 5
- 目前只有一个 reasoning effort 等级（"max"），意味着每次调用都会全量推理
- Simon 指出：现在的鹈鹕测试已经不能用来比较模型了（因为大家都会画了），**真正重要的基准是 agentic tool calling 和长对话中的工具可靠性**

**2. GPT-5.6 家族 (Luna/Terra/Sol)**
OpenAI 7月9日发布的旗舰模型，三个尺寸。Simon 的要点：
- 核心卖点是**长时间 agentic 性能** — Agents' Last Exam 上 Sol（max推理）以53.6分超越 Fable 5（40.5分），且 medium 推理下成本只要1/4
- 新API功能值得关注：**Programmatic Tool Calling**（模型可以组合运行JavaScript来编排工具调用）、**Multi-agent**（子agent并行工作已集成到核心API）
- 但 SWE-Bench Pro 上 Fable 5（80%）碾压 Sol（64.6%），OpenAI 为此专门发文质疑该基准存在~30%的有问题题目
- Simon 的实测感受：Sol 很强，但在复杂编码任务上"还没觉得比 Fable 好"

**3. sqlite-utils 4.0 — 数据库迁移功能**
Simon 发布了 sqlite-utils 4.0，引入 database migrations、嵌套事务、组合外键。这个项目的设计思想值得 PM 学习：**从简单开始，逐步演进**（migrations 特性先作为独立包 sqlite-migrate 验证了3年才合入主库）。

### arXiv 论文速递 (7月15日)

**1. Hindcast: Replaying Prediction Markets to Evaluate LLM Forecasters**
-> 提出了一种全新的 LLM 评估方法：通过回放预测市场（Polymarket）问题，用冻结的 Reddit 快照做检索上下文，完美排除了 data leakage。**结论：一旦堵住信息泄露，检索帮助很大，但仅限于 Reddit 事前讨论过的事件；如果只有猜测，检索反而有害。** 对评估方法论有深远意义。

**2. Deep Interaction: An Efficient Human-AI Interaction Method for Large Reasoning Models**
-> 提出一种让人**直接编辑模型推理链**的交互方法（不是重新生成），修正错误部分的同时保留正确推理。STEM任务上纠错成功率提升25%+，token用量降低约40%。对理解"AI产品中的人机协作"很有启发。

## 🚀 值得关注的项目

### 1. xai-org/grok-build ⭐12,016 (3天前创建)
**xAI 的 coding agent 框架 + TUI**
Rust 实现，全屏鼠标交互、可扩展。这是 xAI 对标 Claude Code / Codex CLI 的产品。**为什么值得看：** coding agent 赛道三巨头（Anthropic、OpenAI、xAI）已全部入局。xAI 的技术路线是 Rust（比 Claude Code 的 TypeScript 和 Codex CLI 的 Python 性能更好？），而且 Grok 3 的推理能力加上这个工具，值得关注它对现有格局的影响。
**对 PM 的参考价值：** 理解 coding agent 的能力边界和产品形态，对未来做 AI 开发工具的产品设计有直接参考。

### 2. Fei-Away/Codex-Dream-Skin ⭐5,296
**Codex CLI 的美化皮肤/主题**
虽然看起来是个"换皮"项目，但 5 天 5000+ 星说明：**开发者对 coding agent UI 的审美和体验有强烈需求**。产品经理的启示：AI 工具的功能和体验同样重要，UI 细节（字体、配色、动效）直接影响用户是否愿意日常使用。

### 3. MDX-Tom/gpt-5.6-instruct
**GPT-5.6 Sol 的 Codex CLI 破甲提示词 + 测试包**
双语项目（中英），针对 GPT-5.6 系列的 jailbreak prompt 和测试套件。反映了社区对模型安全边界和技术限制的持续探索。**对 PM 的意义：** 理解模型的"安全护栏"在哪里，才能设计出既安全又好用的产品。

## 🎯 PM 成长建议

**今天最重要的一个建议：花30分钟了解 Programmatic Tool Calling 和 Multi-agent API**

为什么？
- GPT-5.6 新增的 **Programmatic Tool Calling**（让模型用 JavaScript 编排工具调用）和 **Multi-agent**（子agent并行工作）是 OpenAI 从 API 层面直接内化了 agent 模式。这不再是实验性功能，而是进入正式产品的能力。
- Simon Willison 特别提到：Programmatic Tool Calling "sounds to me like it could help bridge the gap between MCPs and full terminal sessions that can compose CLI utilities in useful ways"——这意味着 agent 系统架构正在平台化。
- 作为 AI 产品经理，理解"模型能做多复杂的 agent 任务"而非"模型能答多难的考试题"，才是区分 2026 年产品能力的关键指标。

**本周可执行的小目标：**
1. 打开 OpenAI 开发者文档的 [Programmatic Tool Calling](https://developers.openai.com/api/docs/guides/tools-programmatic-tool-calling) 页面，读 15 分钟
2. 然后用 Claude Code 或 Hermes 做一个最简单的 demo：让模型调用一个 JS 函数去搜索本地文件，再基于结果做决策
3. 写一条记忆笔记到 wiki：对比一下 OpenAI 的 Multi-agent API 和 Hermes 的 delegate_task 有什么异同

**第二建议：理解 grok-build 的架构**
花 15 分钟读 grok-build 的 README（https://github.com/xai-org/grok-build），重点看它的 extensibility 设计和 TUI 交互方式。对比你现在用的 Claude Code / Codex CLI，思考：如果让你设计一个 AI 编码助手，有哪些 UX 决策是产品经理必须参与的？
