## 📰 今日AI观点

### Simon Willison 博客

**Kimi K3 发布（2.8万亿参数，开源承诺7月27日）**
Moonshot AI 发布了号称"首个开源3T级模型"的Kimi K3（实际2.8T参数），定价$3/$15每百万tokens（输入/输出），是目前中国AI实验室发布的最贵模型，直逼Claude Sonnet系列。Artificial Analysis报告称其"long-horizon knowledge work"评测Elo达1547，仅次于Claude Fable 5。有意思的是：Willison用他的"鹈鹕骑自行车"基准测试跑K3，花了25美分和13,241个推理token——比Claude Fable 5贵不少。他的核心提醒：**不要用鹈鹕测试来比较模型，它无法反映agentic tool calling的能力**。

**GPT-5.6 家族（Luna/Terra/Sol）GA**
OpenAI 发布三个规模等级的GPT-5.6。关键亮点：API新增Programmatic Tool Calling（模型可以写JavaScript来编排工具调用）、Multi-agent（子agent模式直接内建到API）、Prompt Cache Breakpoints（支持手动设置缓存断点）。Willison说这让他想起Anthropic之前加的dynamic filtering机制——趋势很明显：**API层正在原生支持agent模式，不再需要开发者自己拼装**。

**sqlite-utils 4.0 发布背后：Claude Fable 5 贡献了大幅代码**
Willison分享了非常具体的使用AI编码助手的经验：他让Claude Fable 5做pre-release review，Fable写了12个测试脚本，发现了4个release blocker和10个额外bug（包括一个数据丢失的delete_where事务bug）。他说："我确信sqlite-utils 4.0的质量远超没有前沿模型辅助的版本。" 让Claude Code和Codex互相对对方的代码做review也是一个持续有效的模式。

### Lilian Weng 博客

最新三篇：
1. **Harness Engineering for Self-Improvement**（2026-07-04）—— 讲如何设计"harness"（训练/推理框架）让模型实现自我改进。对理解RLHF之外的self-play、self-training范式很有价值。
2. **Scaling Laws, Carefully**（2026-06-24）—— 最新scaling law分析，讨论在test-time compute时代，scaling law是否仍然成立。
3. **Why We Think**（2025-05-01）—— 关于CoT、推理时扩展的深度分析。

Weng的博客始终保持"清晰解释前沿技术"的风格，每一篇都值得精读。

### arXiv 最新论文（7月16日提交）

1. **"Partition, Prompt, Aggregate: Statistical Self-Consistency in Language Models"** — 发现LLM在分区聚合估计中普遍违反基本的概率一致性（"macro fallacy"现象）。提示工程领域的重要发现。
2. **"RoboTTT: Context Scaling for Robot Policies"** — NVIDIA+李飞飞团队，将机器人策略的visuomotor context扩展到8K时间步，性能提升87%。提出"context length as a new scaling axis"。
3. **"Pretraining Data Can Be Poisoned through Computational Propaganda"** — 证明通过公开讨论界面可以注入恶意内容污染预训练语料库。AI安全的重要研究。

## 🚀 值得关注的项目

### 1. obra/superpowers ⭐257K
Anthropic CEO Dario Amodei的兄弟创办的项目。"An agentic skills framework & software development methodology that works." 这是一个强调"skills"（可复用的AI技能/工作流）的框架，和Hermes Agent的skill体系异曲同工。**为啥PM要看**：理解了skills框架的设计理念，就能理解下一代AI产品如何封装"可复用的能力"。

### 2. langchain-ai/openwiki ⭐12.4K
LangChain 出品，CLI工具自动为代码库编写和维护agent文档。名字很直白：让AI agent自己写wiki。**PM视角**：这代表了"AI-native文档"的趋势——不再是写给人看的README，而是写给AI agent看的结构化文档。你在写PRD或知识库时也可以借鉴这个思路。

### 3. XiaomiMiMo/MiMo-Code ⭐12.2K
小米的MoE模型+Agent协同框架。"Where Models and Agents Co-Evolve." 国内大厂在开源agent基础设施方面越来越认真。**PM视角**：关注国产模型+agent生态的演进，Kimi K3和MiMo代表了两种不同路径。

### 4. cobusgreyling/loop-engineering ⭐8.6K
"Practical patterns, starters & CLI tools for loop engineering with AI coding agents." 这个项目和你日常使用Hermes/Claude Code的体验直接相关——它系统性整理了"人-AI协作循环"的设计模式。

## 🎯 PM成长建议

### 今日核心洞察：Agentic API 正在成为标准

从今天的多个信号——GPT-5.6的Programmatic Tool Calling和多agent API、Kimi K3的reasoning token开销、Willison用Claude Fable和Codex互做review——可以得出一个清晰结论：

**AI产品的"能力层"正在从模型能力向"编排能力"转移。**

过去半年最被低估的趋势不是模型参数增长了，而是API层原生内嵌了agent模式。这意味着：
- 对PM来说，"写一个调用LLM的API"不再是技术壁垒
- 真正的产品壁垒在于：工具编排的设计、上下文管理的策略、多agent协作的工作流

### 本周可执行的小目标（30分钟）

**立刻做：fork XiaomiMiMo/MiMo-Code 或 langchain-ai/openwiki，本地跑通一个demo。**

- 选openwiki的理由：它和你正在做的知识库/文档管理工作直接相关。跑通后观察：AI agent如何自动组织和维护文档？这种能力映射到你的PRD知识库管理上有没有借鉴价值？
- 具体操作：`git clone https://github.com/langchain-ai/openwiki` → 看README → 跑一个demo → 记下你觉得"这个模式可以移植到我的工作流中"的1-2个点

### 本周阅读建议

花30分钟精读 Lilian Weng 最新那篇 **"Harness Engineering for Self-Improvement"**。如果你时间少，至少看Introduction + Conclusion。理解"self-improvement"的技术路径能帮助你在面对工程师讨论"self-play训练"、"RLHF改进方案"时具备判断力。
