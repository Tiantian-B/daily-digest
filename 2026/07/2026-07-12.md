### Simon Willison 博客
**最新博文："The new GPT-5.6 family: Luna, Terra, Sol" (Jul 9)**

- OpenAI 发布了三款 GPT-5.6 模型：Luna ($1/$6 每百万token)、Terra ($2.50/$15)、Sol ($5/$30)。Simon 的评价很直白——"price-per-million tokens doesn't tell us much now that the number of reasoning tokens can differ so much"。这意味着模型定价已经变成动态博弈。
- 关键亮点：Sol 在 Agents' Last Exam 上以 53.6 分击败 Claude Fable 5（40.5分），但在 SWE-Bench Pro 上只有 64.6%（Fable 5 是 80%）。OpenAI 为此专门发文质疑 SWE-Bench Pro 有 ~30% 的任务是坏的——benchmark wars again。
- **Simon 的原话金句**："I've had some early access to GPT-5.6 Sol - it's definitely very competent, though so far it hasn't struck me as better than Fable at the kind of complex coding tasks I've been using with Anthropic's model."
- 新 API 功能值得关注：Programmatic Tool Calling（模型可以组合运行 JS 编排工具调用）、Multi-agent（子代理模式原生支持）、Prompt cache breakpoints（显式缓存断点）。
- 其他近期博文：sqlite-utils 4.0 是他用 Claude Fable 写的（总花费约 $149.25），"Relentlessly proactive" 成为他对 Fable 的描述关键词。他还用 Claude Code 把 Moebius 0.2B 图片修复模型移植到了浏览器。

## 🚀 值得关注的项目

### 1️⃣ ponytail (⭐80k+)
"让你的 AI agent 像最懒的高级工程师一样思考。最好的代码是你没写的代码。"——这本质上是**效率优先**的 agent 设计哲学，与"shadcn/improve"的分层路由理念异曲同工。对 AI PM 的启发：产品设计要围绕"用最少 token 解决最多问题"来思考。
→ https://github.com/DietrichGebert/ponytail

### 2️⃣ shadcn/improve (⭐7.8k)
"用最强模型审计你的代码库，为廉价模型写执行计划。"——这是 LLM 领域的**分层能力路由**模式。对 PM 的价值：它背后是一个通用架构设计模式——把"判断"和"执行"拆开，前者用最聪明的模型，后者用性价比最高的模型。完全可以用来思考 AI 产品的成本架构设计。
→ https://github.com/shadcn/improve

### 3️⃣ loop-engineering (⭐7k)
代码循环工程的实用模式、starter 和 CLI 工具。覆盖了 AI coding agents 的完整工作流模式。如果你在用 AI 写代码，这里面的 "Spec-first development" 和 "TDD with AI" 模式可以直接复用。
→ https://github.com/cobusgreyling/loop-engineering

### 4️⃣ omnigent-ai/omnigent (⭐7k)
开源 AI agent 框架和 meta-harness，可编排 Claude Code、Codex、Cursor 等多个编码 agent。多 agent 编排正在成为新的基础能力。
→ https://github.com/omnigent-ai/omnigent

### 5️⃣ XiaomiMiMo/MiMo-Code (⭐11.8k)
小米的 MiMo 模型——"Where Models and Agents Co-Evolve"。模型和 agent 共同演化的理念，说明中国大厂在 agent 化方向上也投入了大量资源。
→ https://github.com/XiaomiMiMo/MiMo-Code

## 🎯 PM成长建议（今天最重要部分）

### 1. ⚡ 今天就去 fork 跑一个项目
**fork `shadcn/improve`**（https://github.com/shadcn/improve）。花15分钟读它的 README 理解"最强模型审计→廉价模型执行"的分层策略。这是 PM 级别的架构思维——不只是一行命令，而是一个能力调度的设计模式。

### 2. 📖 Simon Willison 的 GPT-5.6 分析值得精读
关键认知升级：**模型评估从"看价格表"变成了"看实际场景下的 end-to-end cost-per-completion"**。同一个模型，不同 reasoning level 的成本可以差 100 倍（从 0.71 美分到 48.55 美分）。作为 PM，你需要建立对模型成本的实际感知，而不是背参数。

### 3. 🧪 本周30分钟实践
从 `cobusgreyling/loop-engineering` 挑一个 pattern（比如 "TDD with AI"），用你手上的 Hermes Agent 实际跑一遍。记录：
- 从 prompt 到完成花了多少轮对话？
- 成功率多少？
- 哪一步最花时间？

这样你就能建立对 AI coding 效率的 **量化感知**——这是 PM 的终极武器。

### 4. 🧠 UniClawBench 的5个能力维度 = 你的产品检查清单
Skill Usage / Exploration / Long-Context Reasoning / Multimodal Understanding / Cross-Platform Coordination。下次评估 AI 产品或设计功能时，用这5个维度过一遍你的方案，会非常有帮助。
