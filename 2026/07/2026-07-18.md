## 📰 今日AI观点

### Simon Willison's Blog — 3 篇精选

**1. Kimi K3, and what we can still learn from the pelican benchmark** (Jul 16)
- Moonshot AI 发布 2.8T 参数的 Kimi K3，号称"首个开源 3T 级模型"，7月27日开源。定价 $3/$15 per M tokens，是目前中国AI实验室最贵的模型，与 Claude Sonnet 系列相当
- Artificial Analysis 评测：K3 在长周期知识工作评估中 Elo 1547（+732 对比 K2.6），仅次于 Claude Fable 5；但在 SWE-Bench Pro 上结果不突出
- Simon 用"pelican riding a bicycle"测试跑了一遍，只花 25 美分，但输出 13,241 个 reasoning tokens → 说明 K3 目前只有"max"一个推理力度，很耗算力。核心观察：**pelican benchmark 已经不再能预测模型实际能力了，真正重要的维度是 agentic tool calling 和长对话可靠性**
- ⭐ Simon 的金句："Don't go using pelicans to compare models！" — 以及更重要的方法论："A single prompt can still reveal interesting model characteristics — cost estimate, reasoning depth, vision quality."

**2. The new GPT-5.6 family: Luna, Terra, Sol** (Jul 9)
- 三个尺寸：Luna $1/$6 → Terra $2.50/$15 → Sol $5/$30 per M tokens。最大亮点：**Agents' Last Exam 上 Sol 以 53.6 分击败 Claude Fable 5（40.5分）**，即使在 medium reasoning 下仍领先 11.4 分且成本仅 1/4
- 新 API 特性值得关注：Programmatic Tool Calling（让模型自己编排 JS 工具调用链）、Multi-agent（API 原生支持子 agent 模式）、Prompt cache breakpoints（显式缓存断点）
- Simon 实际体验：Sol 很强，但"doesn't strike me as better than Fable at complex coding tasks"

**3. sqlite-utils 4.0: database schema migrations** (Jul 7)
- Simon 分享了一个非常务实的 AI 编码工作流：用 Claude Fable 写代码 → 用 GPT-5.5 交叉审查 → 再用 Claude Fable 修复发现的 bug。**他承认之前认为"用一个模型审另一个模型"很荒谬，但实践证明真的有效**
- 整个 sqlite-utils 4.0 的开发花费 $149.25（Claude Fable API 成本），大量使用子 agent 并行工作
- ⭐ 关键教训："Release notes are a great example of writing that I'm OK to outsource to agents because they need to be boring, predictable and accurate."

### arXiv 最新论文 (Jul 16)

1. **Partition, Prompt, Aggregate: Statistical Self-Consistency in Language Models**
   — 研究发现 LLM 的概率估计违反基本的统计自洽性（全概率公式），存在"macro fallacy"：细粒度子群体提示的估计反而比直接提问更准确。作为评估 LLM 的新 criterion 有潜力。
   🔗 http://arxiv.org/abs/2607.15277

2. **RoboTTT: Context Scaling for Robot Policies** (NVIDIA + Li Fei-Fei)
   — 把 TTT (Test-Time Training) 扩展到机器人策略，将视觉-运动上下文从单步扩展到 8K timesteps。新的 scaling axis：context length。长上下文比短上下文好 62%。
   🔗 http://arxiv.org/abs/2607.15275

3. **Pretraining Data Can Be Poisoned through Computational Propaganda**
   — 证明通过公共讨论界面（如论坛、评论区）可以对 LLM 预训练数据投毒。提出了 HalfLife 分析框架用于评估恶意内容是否被爬虫纳入训练集。
   🔗 http://arxiv.org/abs/2607.15267

4. **SciDiagramEdit: Learning to Edit Scientific Diagrams from Paper Revisions**
   — 从 arXiv 论文版本历史中挖掘"before/after"图表修改对，训练 AI agent 根据自然语言指令编辑科研图表。用 skill evolution 多轮学习提升准确率。
   🔗 http://arxiv.org/abs/2607.15272

5. **SceneBind: Binding What and Where Across Vision, Audio and Language**
   — 全模态场景表征，同时编码语义（有什么）和空间（在哪里），支持跨模态场景检索和物体定位。
   🔗 http://arxiv.org/abs/2607.15265

## 🚀 值得关注的项目

### Top 3

**1. T3MP3ST ★4896** — 自主红队测试平台
- 多 agent 协作的对抗安全测试框架，TypeScript 实现
- 🎯 **AI PM 价值**：Agent 能力爆发式增长 → 安全红队需求随之爆发。理解 T3MP3ST 的架构 ≈ 理解"AI 安全评估"这个产品赛道的基础设施长什么样。如果你在做 AI 产品，安全迟早是你绕不开的 feature
- 🔗 https://github.com/elder-plinius/T3MP3ST

**2. sim-use ★935** — AI Agent 操作 iOS 模拟器
- 给 AI Agent "眼睛和手"，让 LLM 看屏幕截图后直接操作 iOS Simulator 和 Android 模拟器/真机
- 🎯 **AI PM 价值**：这是"Computer Use"思路在移动端的落地。Anthropic 有 Computer Use，OpenAI 有 CUA，Apple 有 Ferret UI —— 但这是开源实现。很快你会看到产品经理设计"AI 替你点 App"的功能，现在看源码比到时候追方案快 10 倍
- 🔗 https://github.com/lycorp-jp/sim-use

**3. agent-pulse ★205** — AI 行业情报日报
- 证据驱动的 AI 行业情报系统：追踪趋势、数据源更新、每日刷新、每周决策简报。TypeScript 实现
- 🎯 **AI PM 价值**：这正是你作为 AI PM 需要的信息基础设施！与其每天手动刷刷刷，不如部署一个 agent-pulse 这样的工具来替你做竞争情报的收集和结构化
- 🔗 https://github.com/barretlee/agent-pulse

## 🎯 PM成长建议

### 本周可以做的 30 分钟小目标：去读 sim-use 的源码

**为什么是这个？**

两个维度看：

**产品维度：** sim-use 代表的"AI Agent 直接操作设备"能力正在快速成熟。上个月 Anthropic 升级了 Computer Use，本周 OpenAI 推出 Programmatic Tool Calling，sim-use 让你在本地就能跑通"LLM 看到屏幕 → 决定下一步 → 操作界面"这个闭环。作为 AI PM，**这个闭环就是你未来设计产品的底层能力**——无论是"AI 帮你测试 App"还是"AI 帮你填表单"，本质都是这一层。

**趋势维度：** 今天的 arXiv 论文 RoboTTT（上下文扩展到 8K timesteps）和 sim-use 放在一起看就更清楚了 —— **Agent 的"感知-决策-行动"能力在同时从三个方向进步**：上下文长度（RoboTTT）、设备操作（sim-use）、安全治理（T3MP3ST）。这三个方向互相强化，决定了接下来 6 个月哪些 AI 产品能做成。

**30分钟学习计划：**
1. (5min) 读 sim-use README + 看 demo gif
2. (10min) 梳理架构：截图输入 → LLM 推理 → UI 操作映射
3. (10min) 对比 Anthropic Computer Use 的协议差异
4. (5min) 写下：如果你是 PM，会申请什么资源来做一个"AI App 测试助手"的 MVP？

**一句话总结你今天应该带走的东西：**
> Agent 能力越强 → 安全需求越大 → PM 越早动手实验越有优势。别等它变成标配才去研究。
