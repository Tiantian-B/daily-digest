### Simon Willison: GPT-5.6 三件套发布 & AI辅助编程实战

**GPT-5.6 家族 (Luna/Terra/Sol) 来了**
OpenAI 发布了新旗舰系列，分 Luna($1/$6 per M tokens)、Terra($2.50/$15)、Sol($5/$30) 三个尺寸，百万 token 上下文窗口。核心卖点是 agentic 长任务性能——Sol 在 Agents' Last Exam 上以 53.6 分超越 Claude Fable 5 (40.5 分)。但 Simon 本人实测感觉："so far it hasn't struck me as better than Fable at the kind of complex coding tasks I've been using with Anthropic's model"——hands-on 体验和 benchmark 仍有差距。OpenAI 还特别发文质疑 SWE-Bench Pro，称约 30% 的任务存在缺陷，暗示 Fable 5 在那上面的领先可能不靠谱。

**新 API 特性值得关注**：Programmatic Tool Calling（允许模型动态编写 JS 编排工具调用）、Multi-agent（子 agent 模式内建到 API 中）、Prompt cache breakpoints（Claude 式的显式缓存标记）。

**Claude Fable 协助 sqlite-utils 4.0 的实战经验**：这篇可能是今天最有价值的。Simon 分享了他如何用 Claude Fable 5 完成 sqlite-utils 4.0 的最终审查和发布，全程约 $149.25 的 API 成本。关键教训：
- Fable 5 写了 12 个测试脚本、发现 4 个 release blockers 和 10 个额外问题
- Simon 发现让 Fable 审 GPT 的工作（或用 GPT 审 Fable 的工作）"it really does work"——交叉模型审查已成为他的习惯
- 文档外包给 AI 写：release notes 和 upgrade guide 完全由 AI 编写，"I've slowly become comfortable outsourcing this kind of documentation to the robots"——但前提是 "doesn't need to convince people of anything, or express any opinions"
- 37 个 prompt、34 个 commit、+1321/-190 行代码变更，全程用 Claude Code for web 在 iPhone 上操作，甚至出门看 July 4th parade 时 QA

**核心启示**：AI coding agents 的 sweet spot 不是从零写代码，而是做代码审查、补齐测试覆盖、发现一致性问题。Simon 说 Fable "has really good taste in API design"。

## 🚀 值得关注的项目

### 1. ponytail ⭐84k — 让 AI agent 像最懒的资深工程师一样思考
> https://github.com/ponytail/ponytail

**为什么值得看**：这个项目试图解决 agent 过度工程化的通病——LLM agent 经常做"比要求的更多"，读了一堆不需要的文件。ponytail 反其道而行，让 agent 思考"如果我是那个想少干活的老手，我会怎么做"。这和今天的论文 arXiv:2607.13034（E3 benchmark）精神一致——让 agent 学会判断任务复杂度，避免浪费 tokens。

**对 AI PM 的参考价值**：成本优化是 agent 产品落地的核心痛点。这个方向（complexity-aware execution）直接关系到 LLM 产品的毛利。

### 2. colibri ⭐14k — 在消费级硬件上跑 744B MoE 模型
> https://github.com/colibri/colibri

纯 C 实现，在 25GB RAM 的消费级机器上运行 GLM-5.2 (744B MoE)。如果你关心模型部署成本、边缘计算、或"如何在有限硬件下跑大模型"，这是必看项目。

### 3. MiMo-Code ⭐12k — 模型和 agent 共进化
> https://github.com/MiMo-Code/MiMo-Code

"Where Models and Agents Co-Evolve"——名字就值得关注。从小米 MiMo 模型出发，探索 coding agent 的进化路径。对 PM 来说，这代表了 AI 工具的下一代范式：不是在固定模型上搭 agent，而是模型和 agent 相互促进迭代。

### 4. loop-engineering ⭐8k — AI 编码的循环工程模式
> https://github.com/loop-engineering/loop-engineering

Practical patterns for loop engineering with AI。如果你日常用 Claude Code / Codex / Hermes 写代码，这个 repo 的 patterns 和 starters 可以直接拿来用。tags: agentic-ai, ai-agents, ai-coding, automation。

### 5. improve ⭐8k — 最强模型审计代码库
> https://github.com/improve/improve

"Use your most capable model to audit your codebase and write plans for improvement." 和 Simon 的实践吻合——AI 的甜点不是写代码，而是当 code reviewer。如果你是 tech PM 或负责团队代码质量，值得看看这个工具如何融入 workflow。

## 🎯 PM 成长建议

**1. 核心洞察：Complexity-aware execution 是 agent 落地的关键瓶颈**

今天 Simon Willison 和 arXiv 论文 E3 都指向同一个问题：AI agent 不知道什么时候该使劲、什么时候该省着用。对于产品经理，这意味着你在设计 AI 功能时，需要把"成本感知"作为一等公民来考量——不是所有任务都需要强模型，不是所有场景都要多步推理。

**2. 本周可执行的小目标（30 分钟内）：**

**👉 Fork `ponytail` 或看看 `E3` 论文的代码仓库，理解 complexity-aware routing 的工程实现**

具体做法：
```
# 打开 ponytail 的 README，花 15 分钟理解它的核心思路
# 然后对比你当前负责的产品中，哪些场景可以用这种"先估难度再执行"的模式
# 比如：搜索场景可以分"简单问答 vs 复杂分析"，路由到不同模型
```

**3. 跨模型审查工作流——今天就从自己项目开始**

Simon 说让一个模型审另一个模型的工作"真的有效"。实际操作：
- 下次你让 Claude Code 写了一个小功能后，把代码贴给 GPT（或反过来）
- 花 10 分钟看两边挑出的问题是否不同
- 记录下哪个模型擅长发现哪类问题（比如 Claude 更擅长 API design taste，GPT 更擅长 edge cases）

这个习惯养成后，你能更精准地知道"这个任务该用哪个模型"，直接提升工作效率。
