## 📰 今日AI观点

### Simon Willison — GPT-5.6 实战测评 & 编码代理经验

**1. GPT-5.6 三件套发布 (Luna/Terra/Sol)**
OpenAI 发布了三个尺寸的新模型，价格从 Luna $1/$6 到 Sol $5/$30 每百万 tokens。百万 token 上下文窗口，128K 最大输出。在 Agents' Last Exam 上三款全部超越 Claude Fable 5，但 SWE-Bench Pro 上 Fable 5 (80%) 碾压 Sol (64.6%)。Simon 的原话：「Sol 确实很强，但在复杂编码任务上目前还没觉得比 Fable 好」。新 API 特性值得关注：Programmatic Tool Calling（模型能写 JS 编排工具调用）、Multi-agent（原生子代理模式）、Prompt cache breakpoints（可控缓存断点，类似 Claude 模式）。

**2. shot-scraper video：让 AI 自己录产品演示视频**
Simon 发布了 shot-scraper 1.10，支持用 YAML storyboard 自动录制 Web 应用演示视频。整个 storyboard 由 GPT-5.5 自动生成，完美展示了「coding agent + CLI 文档」的协作模式。他说：「如果没有编码代理支持，这个功能我几乎肯定不会去做」——这是 PM 理解 AI 生产力的关键洞察。

**3. Moebius 浏览器端图像修复模型**
用 Claude Code 把 0.2B 的 PyTorch 模型移植到 WebGPU 浏览器运行。更值得关注的是他的工作流：等 Codex 做大型重构时，用碎片时间并行搞了个副项目。

## 🚀 值得关注的项目

### 1. affaan-m/ECC — Agent 性能优化系统 (229K⭐)
**为什么值得看：** 号称「编码代理的性能优化系统」，集成了 skills/instincts/memory/security。2026 年 GitHub 最火项目之一。对 AI PM 的价值在于：它展示了 AI Agent 从「能用」到「好用」需要什么——不是更好的模型，而是更好的工具链和编排机制。

### 2. JuliusBrussee/caveman — Token 优化技巧 (89K⭐)
**为什么值得看：** "why use many token when few token do trick"——用原始人语风写 Claude Code skill，砍掉 65% tokens。对 PM 的启发：prompt 工程的极致压缩方法，直接关系到 AI 产物的成本结构。这个思路完全可以用在产品 prompt 设计中。

### 3. MemPalace/mempalace — 开源 AI 记忆系统 (57K⭐)
**为什么值得看：** 号称「基准测试最佳的开源 AI 记忆系统」。对于任何做 Agent 或长对话场景的 PM，记忆机制是核心产品差异点——怎么存、怎么取、什么时候遗忘。开源实现是研究产品化思路的最佳教材。

### 4. headroomlabs-ai/headroom — Token 压缩 (58K⭐)
**为什么值得看：** 压缩工具输出/日志/文件/RAG chunk 60-95% 而答案不变。直接转化为你的 API 成本节省。对于 B2B SaaS PM，这是了解「如何在客户预算内交付 AI 价值」的实用工具。

### 5. karpathy/autoresearch — AI 自动研究 (91K⭐)
**为什么值得看：** 在单 GPU 上自动跑 nanochat 训练研究的 AI Agent。Karpathy 出品，质量保证。展示了 AI Agent 从编码到研究的升维路径。

## 🎯 PM 成长建议

### 核心洞察：今天最重要的一个趋势

**「编程代理的体验正在重塑我们对 AI 能力的认知」——Simon Willison 的实战经验是最好的教材。**

两条信号指向同一个方向：
1. GPT-5.6 Sol 在 Agents' Last Exam 上力压 Fable 5，但在 SWE-Bench Pro（真正复杂的编码场景）上被 Fable 5 碾压
2. Simon 用 GPT-5.5 自动构建 shot-scraper video 的 YAML storyboard，整个功能没有编码代理他「几乎肯定不会去做」

**结论：模型评测的「基准」和「真实体验」正在脱钩。作为 AI PM，你不能只看榜单，要自己上手用。**

### 本周可执行的小目标（30分钟）

**任务：亲自安装并体验 JuliusBrussee/caveman 的 Claude Code skill**

步骤：
1. 打开 Claude Code（或 Codex）
2. 在项目根目录创建 `.claude/skills/` 目录
3. 从 caveman 项目复制或参考其 CLAUDE.md 中 token 压缩的思路
4. 找一个你最近用 AI 写的 PR 或文档，对比「正常 prompt」和「caveman style prompt」的 token 消耗和输出质量

**为什么是这个任务？** 因为它让你亲身体验：
- Token 经济学：同样的任务，不同的 prompt 策略成本差 65%
- Agent 配置化：理解 SKILL/CLAUDE.md 在 AI PM 工作流中的杠杆效应
- 产品设计的降维打击：不是模型更强，而是 prompt 策略更聪明

**延伸思考：** 如果你的 AI 产品面向的企业客户要求降低成本，caveman 的思路能否转化为产品 feature（比如「经济模式」开关）？
